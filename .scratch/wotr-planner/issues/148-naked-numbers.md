## Answer

Done 2026-11-11. The numbers are naked. No tool takes `assume` or returns `assumed`: `rules::Assumed`, `GearItem` and the engine's three `assumed_*` lines are gone, with `gear.ron`, the seed's gear tables (dropped by the new migration `20261111152919_148-drop-gear.sql`) and the two fields of `SpellTraits` only gear read (`save`, `mind_affecting`, so `caster` no longer takes them). The `leaves_out` lists just say "gear", and the honesty boundary, in `INSTRUCTIONS` and the build guide, says the numbers count no gear and the attack line's weapon is the Build's Weapon Focus weapon. `sheet` and `compare` without `weapon` give the attack line of the Build's first Weapon Focus weapon (`Engine::default_attack_weapon`, as the web app), naming it, and none without one; `by: {"attack_line": {}}` reads each Build's own. The wotr-build skill compares naked numbers; gear stays the agent's own labelled judgement if the user asks.

Decisions the ticket didn't spell out, each the smaller option:
- `SpellTraits::save`/`mind_affecting`, the `caster` argument's `save`/`mind_affecting` and `CasterLine::caster_level_parts` (MCP `caster_level_counts`) were removed with gear: only gear read or filled them, and an argument that changes nothing would mislead an agent.
- `improve`'s `by` shares `compare`'s shape, so its `attack_line` `weapon` became optional too: it reads the weapon of the Build's Weapon Focus before any option is taken, so every option is priced on one weapon (each option's own only when the Build has none yet).
- `attack_leaves_out` comes whenever an attack line does (on `compare`, when any summary has one, or a `weapon` was given).

After merging, the main session rebuilds its database (a new migration) and runs `scripts/build-mcp.sh`.
